# Rigorous Dev Local Settings (Example)

This is an example configuration file for the Rigorous Dev plugin.

## How to Use

1. Copy this file to `.claude/rigor.local.md` in your project
2. Customize the YAML frontmatter settings above
3. Add project-specific notes in the markdown section below

**Note:** The `.claude/rigor.local.md` file is gitignored by default, so your local preferences won't be committed.

## Configuration Options

### `artifacts_directory` (DEPRECATED — moved to project table)

The `artifacts_directory` setting is now stored in the `project` table in the rigor database (default: `docs/sdlc`). It is set during `/rigor:start` or `/rigor:onboard` and stored via the `iteration_create` MCP tool. This file is no longer consulted for artifact directory configuration.

### max_iterations

**Type:** number
**Default:** 3

Maximum producer-critic iterations before escalating to user for guidance.

**Range:** 1-10 (3 recommended)

### auto_save

**Type:** boolean
**Default:** true

Whether to automatically save workflow state after each phase transition.

**Options:**
- `true` - Auto-save (recommended)
- `false` - Manual save via `/rigor:dev-status`

### default_project_name

**Type:** string
**Default:** Current directory name

Default project name to use when starting a new workflow.

**Example:** `"My Awesome Project"`

### critic_model

**Type:** string
**Default:** `"sonnet"`

Model to use for critic agents during producer-critic validation loops. Producer agents always inherit the parent model.

**Options:**
- `"sonnet"` — Best balance of quality and cost. Critics follow checklists and produce structured verdicts; Sonnet handles this reliably. **(Recommended)**
- `"haiku"` — Budget-friendly. Good for small projects or when you plan to review artifacts carefully yourself. May miss nuanced quality issues.
- `"opus"` — Maximum rigor. For mission-critical or regulated projects wanting the most thorough critic review.
